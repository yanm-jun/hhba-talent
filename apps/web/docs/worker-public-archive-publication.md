# HHBA 劳动者权益公开档案：数据与发布边界（V4.1）

## 已支持
- 正式入口：`/transparency`；访客及个人用户顶部导航可以直接进入。
- `GET /api/transparency/cases`：**只读**可公开的劳动者个案摘要，不读取企业协助模块、履历库或任何私人劳动者材料。
- `GET /api/transparency/ledger`：**只读**经逐项财务核对和隐私审核、并与**已发布月报**对应的可公开资金明细。该表为可自愿公开的明细子集，不是全部银行交易。
- 演示案例仍独立在 `/transparency/archive-preview`，须在响应与 SPA 导航上返回 `noindex,nofollow,noarchive`。
- 过期或错误月份参数不得隐藏其他已发布月报。

## 尚未上线的事项（必须完成后才可显示真实案例与逐笔信息）
1. **独立迁移与回滚验收**：使用与现有月报相同的专用 `HHBA_TRANSPARENCY_DB`，先在测试库验证 `d1/0021_worker_public_archive.sql`；此 PR 不执行 D1 生产迁移。
2. **内部受理资料绝不直接入公库**：人工完成个人授权、事实核验、资料脱敏及审批后，只把允许公开的文字摘要导入 `hhba_worker_public_cases`。未经授权、尚在争议的细节不得发布。
3. **公开门禁**：状态为 `published` 且 consent/fact/privacy 三类审核标志均通过、记录批准人和发布时间，接口才显示。没有满足上述条件的记录不能通过搜索、参数或关联链接被公开。
4. **支付明细门禁**：真实支付凭据、业务用途、审核人员和可公开内容都经过复核，再在 `hhba_fin_public_entries` 中批准发布。**总额仅以审核发布的月报为准**；个别公开记录不得冒充全量银行流水。关联案件只有在同样经过授权的情况下才向外显示案件编号。
5. **后续运营后台**：如需自动发布，必须另行建设有角色隔离、双人审核、留痕、可撤回、修订版本和纠错流程的后台。当前不提供随意导入或公网写入接口。
6. **权限、保密与错误处理**：不公开身份、联系方式、合同/银行资料原件、未授权律所沟通和私下调解内容。无数据库或尚未迁移返回 `state:not_ready`；接口故障为错误状态；无记录但已启用返回 `state:ready` 和空数组。三者在页面中必须区分。

## 数据模型
- `hhba_worker_public_cases`：公开编号、类别、公开标题、阶段、事实摘要、处理摘要、结果摘要和审核/发布时间。
- `hhba_fin_public_entries`：公开编号、关联月报期、收支方向、实际金额（分）、可公开用途、可选且已审核的案件关联、发布审批字段。
- `hhba_fin_reports`：依然是资金汇总唯一权威来源，原有月报计算逻辑不改。

## 验收边界
- 在迁移和授权的真实资料不存在时，页面不能出现真实案例数量或模拟资金总额。
- 28 个 `HHBA-DEMO-...` 编号、模拟收入和模拟支出不得进入上述两张正式数据表。
- 财务与归档合同测试通过不等于生产数据已经完成核验；预览通过后仍需人工检查手机/桌面链接和 HTTP `X-Robots-Tag`。
