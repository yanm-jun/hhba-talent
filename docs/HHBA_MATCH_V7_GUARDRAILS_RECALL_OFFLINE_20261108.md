# HHBA 匹配 V7：资格唯一判断、职位召回与真实评测准备

开发基线：V6 草稿 PR #297 分支（未合并 main）；本次分支可独立验收、不会部署 hhba.work 或开启 AI。

## 1. 资格处理：唯一结构化规则

### 当前问题
旧版扁平必备技能与新版 ALL_OF/ANY_OF/AT_LEAST 条件可能叠加，导致“Python 或 Java 任选一种”被误当成必须两种技能都掌握。职业资格证书也存在相同风险。

### 实际修改
- 在官方 JD 有结构化条件时，其覆盖范围内的技能及证书由条件组**唯一判断**；旧版平铺字段仅负责其他没有被该结构化要求覆盖的明确条件。
- 对结构化条件先保留技能/证照列举和“任选一种”的完整句子，不因逗号自动断句；独立要求仍须单独满足。
- 只有有证据的明确条件才作为资格门槛；缺少简历技能/证书**不是“已证明不符合”**。
- 不修改法定职业资格政策，也不将证书自述视为政府注册核验。

## 2. 地点分类

独立标签 \`MAINLAND_CONFIRMED\` / \`OUTSIDE_MAINLAND\` / \`UNKNOWN\`：
- 明确大陆城市方可进入主要匹配。
- “北京 / 伦敦”“香港”“新加坡”等有境外工作地点证据，应排除。
- 未标注、地点待定、远程但无明确大陆城市，为 **NEEDS_INFORMATION**，提示查官方招聘详情；不会被当作境外已经证实，也不能混入 Top10。
- **目前不主动解锁从源头已拒绝的无地点招聘信息。** 官方 Fetch 和站内审核依然必须先有大陆城市证据；下一步扩大地理召回需要独立的可信来源补全流程，不能通过模糊推断放行。

## 3. 候选多样性和去重

- 按企业、职位、**城市及部门**划分招聘职位；同一企业同名职位跨城市不再被无意合并，确实重复的同城市同部门职位继续去重。
- 每次最多 4 次 Search、8 次 Fetch 不变。在官网 Fetch 预算内，先为不同职业意向保留可用的搜索结果，再按职位标题相关性与公司多样性筛选。
- 搜索片段只用于分配官网抓取次序，不当作岗位存在、工作地点或正在招聘的证据；未抓取并核验官方详情不得进入 Top10。
- 多个独立部门或跨城市岗位仍可能因 Top10 公司多样性上限进入第二轮补位，按照已有逻辑谨慎处理。

## 4. 有证据的职业迁移

- 基于简历中有明确工作行为的原岗位，以及两项以上实际有文字证据的技能，给出少量可迁移职业方向提示。
- 必须用户表达该职业意向，不能仅凭类似岗位名字推断已有目标职业工作经验。
- 迁移提示不加分、不放宽经验、学历、技能、执照、地点审核。
- 目前是**有限的可审计规则**，不是完整职业能力图谱或模型自动训练；后续应依真实脱敏评价样本扩展。

## 5. 离线评价标准

新增（仅对人工标注的已知岗位 ID 计算）：
- Precision@3、Precision@10：推荐前 K 个中已被人工标为相关的比例；
- NDCG@10：能否把高度相关岗位放在更前面；
- Recall@20（仅相对于已标注岗位全集）：找回多少已标注的相关职位；
- Candidate Recall（仅相对于已标注岗位全集）：候选池是否已包含应该看到的岗位；
- 按职业类别聚合；不会输出姓名、原始简历、用户身份或证照号码。

**注意：** 对有限人工标签的召回率，不等于中国市场所有实时有效岗位的总召回率；对模拟测试集的成绩，也不等于真实产品匹配准确率或录用概率。

## 6. 合并、灰度与成本边界

- 新增专项自动化测试并接入现有 GitHub CI；须同时通过既有 V2—V6 回归、前端构建和预览冒烟。
- 现有 Cloudflare 正式生产 AI 服务仍关闭，未经下一轮授权不会开启、调整 API 密钥或新增付费调用。
- V7 在 V6 开发分支之上进行，验收后必须先处理 #297 依赖，再决定是否合并主线。
- 缺少经过授权的真实测试简历及人工标注招聘岗位时，不能宣称达到 >=80% Top3 相关率。
