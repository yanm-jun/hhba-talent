# HHBA Phase 3 PRD：受授权的人才检索与联系申请

## 目标与边界

为已审核企业提供一个极简闭环：**输入一句需求 → 系统整理可确认条件 → HR 确认 → 检索已授权人才 → 查看匹配依据 → 发起站内联系申请**。

Phase 3 不开发公开职位市场、自动邀约、外部 Agent/MCP 人才读取、真实外部模型解析或 ATS 流程。个人端继续以私密简历上传和能力名片为主。

## 角色与准入

- 个人：仅其确认的能力档案可进入候选索引；默认不进入索引。
- 企业成员：必须是 active membership；组织状态必须为 `approved` 才能调用检索和联系。
- 企业管理员：可管理本组织需求、查看本组织检索与联系记录；普通成员按已有角色策略收紧。
- 平台管理员：只审核组织、审计，不可任意读取私密原始简历。

## MVP 用户需求

1. HR 粘贴自然语言需求，界面显示可编辑的条件草稿和“无法可靠判断”的字段。
2. 检索只返回已确认档案且授予 `enterprise_search` 的最小字段：展示名、能力标题、技能、概括性经历、服务方式、匹配理由；绝不返回原始简历、联系方式、未公开字段。
3. 无结果时给出明确空状态与放宽条件入口；低置信度结果必须标识为“条件不完全匹配”，不得伪造评分准确性。
4. 企业只能发起站内联系申请；个人接受后才可以按其选择提供联系方式或继续站内沟通（本期先完成申请/反馈状态）。

## 成功条件

- 检索前服务端强制验证企业审核状态、成员关系及个人授权。
- 个人撤销 `enterprise_search` 后，其索引投影立即不再可查询。
- 每个搜索、结果展示、联系申请及拒绝都产生不含敏感内容的审计事件。
