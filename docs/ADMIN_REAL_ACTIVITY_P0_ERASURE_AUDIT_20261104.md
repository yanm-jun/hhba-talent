## 本分支整改：保护用户撤回选择

1. 点击「拒绝」后先在本地停止采集，再向既有 `DELETE /api/engagement/account` 发送当前账户的删除请求。
2. 只有服务器明确响应 `{ok:true,deleted:true}` 才展示「已确认」；网络错误、会话失效、服务异常都不能冒充删除成功。
3. 失败时允许在原个人隐私页重试。无论删除成功与否，拒绝状态都不应重新开启追踪。
4. 既有 `GET /api/engagement/self-check` 仍为只读，新增当前账户 **是否存在任一历史活动行** 的布尔结果；不会输出账号标识、手机号、搜索词或简历。用户拒绝统计后仍可检查是否清零。
5. 集成测试覆盖：两个真实模拟会话隔离、活动记录创建、同日去重、撤回删除、历史记录清零、其他账号数据保留、收藏独立性以及个人隐私页的重试提示。
6. 不改变主页、原后台、现有指标计算方式、D1 表结构或正式配置。

## 本分支验收边界

- 所有模拟账户与活动仅运行于隔离测试进程；**不是生产用户，也不应进入融资口径**。
- 源码检查和自动化测试不等同于正式用户浏览器体验。需要真实用户本人登录、了解并自愿选择统计授权。
- 生产验证建议：登录 `/candidate/login` → 在 `/candidate/account/privacy` 自愿同意 → 访问岗位/政策/企业 → 查询个人活动 → 由授权管理员核对 `/admin-preview/` 聚合 → 拒绝 → 等待删除确认 → 再查历史是否清零。
- 如保持拒绝状态且查询历史仍存在活动记录，应提示重试、不得显示已删除。
- D1/D7 是首次被授权观察到的活跃回访，不是注册留存率；注册账号数与自愿统计账号数必须分别展示。
- 本分支仅供独立检查与 PR 验收；未经确认不合并正式 `main`、不部署 `hhba.work`。
