# HHBA 企业工厂 V2：固定开发与验收流程（2026-10-30 生效）

> 适用于所有新增、修订企业档案与招聘岗位。此文件是跨会话、跨开发者的执行规范，执行前先阅读。未经用户验收，不得覆盖正式主站或阿里云正式环境。

## 一、唯一开发主线

- **基线**：完整 HHBA 静态网站的 V2 整合分支 `feat/integrate-employer-v2-into-unified-20261030`；不能只沿用旧版 `feat/hhba-unified-static-20261025` 或孤立 `preview-factory-v2`，不得擅自替换完整网站主页。
- **企业资料唯一源**：`apps/web/src/data/employerProfiles/cn-autumn-NNN.json`。仓库的 `.gitignore` 曾忽略 `data/`，**必须 `git add -f` 并以 Git 历史实际文件存在为准**。
- **图片唯一源**：`apps/web/public/images/employer-profiles/cn-autumn-NNN/`。一张准确的品牌 Logo + 两张不同的、可溯源且本地保存的企业相关真实图片；三张文件独立、不拼接、不得将建筑效果图当已建成现状图、不得混淆集团/子公司、不得伪造与企业合作。照片只展示，不跳第三方网站。保留图片来源、版权与拍摄信息的不确定性。
- **共用能力，不要重写单家公司页面**：`ConfiguredEmployerProfilePage`、`HomeCompanyMarquee`、`employerProfiles`、`domesticCompanySearch`、`domesticRebuildJobs` 与 `UnifiedJobMarket` 自动消费 V2 企业资料。除通用模板缺陷外，不为每家复制页面或创建专属搜索系统。

## 二、每家企业必须完成的闭环

1. **核对上一家/现存版本**：确认实际分支、企业编号、当前数据/素材与最后成功验收记录；只做增量。
2. **来源与法律主体**：优先查企业真实官网、年报、官方校招公告、正式委托报名入口；母公司/子公司、品牌/法律主体、历史岗位/当期岗位严格区分，记录查看日期及原始来源。
3. **三张独立图片**：真实品牌标识 + 企业相关照片两张，标注来源和描述，保存到本地静态文件；未实际下载核验不得声称完成。
4. **岗位核实**：尽可能录入官方逐条岗位及 JD；若官方只给大类，则只能明确标识“官方岗位类别”，不臆造职务、工作地、学历和人数；对不在招、历史信息及截止时间加明确标识；专业标签说明“相关不等于符合招录资格”。保留申请官网真实入口且不得绕过既有登录拦截。
5. **自动接入全站**：首页品牌 Logo 轮动、企业资料库、招聘市场搜索、中文单字/简称、英文别名、专业切换、站内岗位详情；企业搜索**独立于岗位是否有通过近期核验的记录**。
6. **浏览器验收**：桌面 + 手机测试布局、文字/图注换行、三张图片加载、无外链照片、招聘链接；测试企业全称、中文 1 字、中文 2 字、英文别名、专业过滤、岗位详情、刷新后 URL 搜索词保留、首页品牌点击。
7. **仅发布完整站的独立 GitHub Pages 验收目录**：`/hhba-talent/preview-integration-v2/`，以现有完整网站作底座而非 V2 单独小站；发布后用浏览器实测公开网址。更新 Pages 前必须先通过当前正式首页及仍在线旧预览文件的“备份一致性”校验，不一致就停止，不能强行覆盖。
8. **用户验收**：提供实际可点击整站预览、招聘搜索链接、企业详情和 GitHub Actions 测试证据。用户检查通过后才合并正式发布分支；阿里云正式上线仅在用户再次确认后由 Muse 执行。

## 三、重复使用的脚本与结构

- `node apps/web/scripts/employer-factory-check.mjs`
- `node apps/web/scripts/factory-v2-validate.mjs --all`
- `python apps/web/scripts/factory-v2-media.py cn-autumn-NNN`（下载校验，需依赖和联网 runner）
- `node apps/web/scripts/factory-v2-browser.mjs`（指定 `HHBA_EMPLOYER_ID` 与 `HHBA_TEST_BASE`）
- `node apps/web/scripts/factory-v2-public-search.mjs`（必须检查真正上线的独立预览地址）
- 完整 Vite 构建、`factory-v2-routes.mjs` 与整站无回归测试。

## 四、每次交付必须说清楚

- 已完成哪些真实工作；哪些未完成，失败或待审核（不得把“提交了 JSON”写成“已完成媒体下载”或“正式站已更新”）。
- 企业数量、具体岗位/岗位类别数量、已核实来源、Logo 与两图可用情况。
- **当前预览与正式静态首页是两套不同环境**。须在可公开访问后才给出验收链接。
- 不因赶进度绕过信息核验或现有主站数据、账号、隐私保护与合规边界。

## 五、失败时的处理原则

发现旧站搜不到、媒体错误、Pages 发布保护阻断、`data/` 未提交、工作流失败、分支冲突：先查完整代码与 CI 日志，保留失败证据，只修通用根因，重跑全站及真实网址验证。未经证据，不得宣布“已经全部解决”。
