# Paid smart-match order and authorization rollout

This is a separate 19.90 CNY smart-match SKU, not the existing apply-credit product. Use existing merchant signing and gateway-response verification. The checkout endpoint validates authenticated ownership; callbacks validate signature, app, seller, exact amount, order ID and provider trade number. A single active order per account and exact HMAC task binding prevent duplicate charging and changing a paid task's input. Continuations and recovery reuse the same task. Explicit close/cancel closes its binding. Payment records are private, not public assets.

Apply 0091_v4_match_orders.sql to the authentication D1 only after preview validation. The two switches HHBA_MATCH_PAYMENTS_ENABLED and HHBA_MATCH_PAYMENT_REQUIRED remain off by default. HHBA_MATCH_ALIPAY_NOTIFY_URL must equal https://hhba.work/api/match-payment/alipay/notify and the merchant must be approved for this SKU. Public asset writes on actual production routes require managed task plus payment-required mode and server-side verified entitlement. Do not activate until outstanding tasks have drained and real merchant acceptance, recovery after payment, cancellation/refund policy and customer support have been verified. No real payment transaction is executed by these tests. OCR/preview is a separate existing path, not the matching model authorization.
