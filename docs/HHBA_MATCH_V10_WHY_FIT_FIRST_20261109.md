# HHBA V10：为什么这个岗位更适合你（体验简化方案）

日期：2026-11-09。开发分支：`feature/match-v8-deepseek-dynamic-official-discovery-20261108`，PR #299（Draft）。

## 用户真正需要的界面
上传简历 → AI 提取已记录的学历、职业方向、技能和经验 → 找到中国大陆企业招聘机会 → 按简历与岗位的参考适配程度展示（至多 10 条）→ **在每条岗位下直接说清楚为什么推荐** → 官方职位链接直接跳转。

不要求用户理解 JD 解析、ATS 供应商、成本计量或学历审核算法。把用户真正需要的「我为何适合」放在结果最显眼位置，不把用户拖进另一层复杂审查界面。

## 本次实际代码变更
1. `match-explanation.js` 新增 `whyThisJob`：用**已通过简历证据提取的技能名称**、与岗位方向关系、岗位明确写出的最低学历/年限生成最多 3 条具体事实依据，并提供最多 2 条待核实项；不把求职意愿说成已任职经历。理由不是录用成功率。
2. `domestic-match-fusion.js` 在最终排名完成后附加 `why_recommended`；不改变现有参考分数与明显不符合硬性要求的岗位处理。
3. 招聘来源只确认了企业入口、并未确认具体 JD 时，`whyThisCareerEntry` 只说明「为什么根据职业方向推荐这个渠道」，不伪称已匹配岗位能力或给出岗位匹配分数。
4. `CandidateMatchResultDialog.tsx` 将**已核验岗位优先排列**，每个结果行直接显示「为什么推荐」，打开详情展示具体简历依据和 2 项待确认条件。导航链接作为补充，而非抢在已匹配岗位之前。用简短文案避免让用户理解复杂技术限制。
5. 搜索预算从原先过于保守的 **3 Search / 6 Fetch** 放宽为 **6 Search / 12 Fetch**，Fetch 最多 3 个并发，避免每次用户交互长时间串行等待。**取消按几分钱成本优化而提前拒绝寻找机会的产品倾向**，但保留每次技术请求的上界、用户身份验证、匿名审计、频次和提供商超时防护，不开放无限循环收费。
6. 不额外生成一段无法核对的模型「彩虹屁」；当前推荐理由来自 AI 已结构化的简历事实与官方岗位已知条件，缺少证据则明确说明，减少假匹配。

## 需要诚实保留的界线
- 站外详情 URL 不等于仍在招；不能把匹配参考分数宣传为录用概率。
- 中国大陆工作地、明确的学历/经验/执业资格硬条件不能由“意向吻合”抵消。
- 不向公开 Search 传送用户简历原文，仍保留上传时一次必要授权。已登录的用户才能执行付费分析。
- 若只有企业招聘主页，不对它编造岗位标题、具体 JD、学历、经验或个人匹配分数。
- 从 6/12 改动尚未进行新一轮收费 DeepSeek 实测，不能把离线合约测试当作真实 Top10。
