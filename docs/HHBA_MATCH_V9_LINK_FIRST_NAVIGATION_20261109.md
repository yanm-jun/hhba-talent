# HHBA · 官方招聘链接优先（V9 Preview）验收记录

日期：2026-11-09。以用户最初希望的形式为核心：**帮助求职者发现中国大陆相关企业招聘机会，直接跳转企业招聘官网或企业确认的招聘租户**，不强迫每条链接先完整读取职位说明。

开发分支：`feature/match-v8-deepseek-dynamic-official-discovery-20261108`，PR #299（Draft），尚未合并 `main`。

## 本次真正改变的产品逻辑

1. 用户仍可上传 PDF/DOCX，勾选原本的必要 AI 分析授权；本地脱敏后 DeepSeek 用于识别求职方向。
2. 新的 `official-recruitment-link-navigation.js` 只向 DeepSeek Search 传入**标准化职业词**，不上传简历、姓名、电话。直接最多 3 次 Search + 6 次 Fetch，**0 次额外模型调用、0 次浏览器渲染**；上限不足时不会人为补齐。
3. 将公开搜索结果分为企业招聘入口与具体岗位链接；搜索结果仍是**线索**，要读取独立的企业招聘页作为来源证据，才可展示。访问未成功、域名可疑、聚合站或海外明显线索不显示。
4. 对飞书等共享 ATS 职位链接，仅当从实际读取的企业官网中能找到**明确指向该职位或企业专属招聘租户**的招聘链接时，才允许展示，不能把全平台认成某个企业的官方站。
5. 前端直接提供外部链接；对“具体岗位链接”只显示“相关岗位/职业”，**不把搜索摘要当作学历、城市、经验或仍在招聘的事实**。对企业招聘首页标明“需自行在官网筛选中国大陆岗位”。
6. 已核验岗位与仅提供导航的企业链接分两条通道。原学历/经验/城市硬审核、匹配分数仅作用于**真正有岗位证据的已核验岗位**，不会为招聘入口生成虚假的成功率或匹配分。
7. 仅在 Cloudflare **Preview** 环境和 `HHBA_MATCH_LINK_NAV_ENABLED=1` 时生效，并继承现有登录、隐私授权、每日限额、Provider 用量估算和 D1 成本记录。Production 开关未开启。

## 验收

- GitHub Actions：[201/201 项自动化测试成功](https://github.com/yanm-jun/hhba-talent/actions/runs/42569192099)；包含完整 TypeScript 构建和原有简历匹配/岗位资格回归。
- 新增 5 项专门的正反例：企业自有招聘域名 + 职位直达、企业招聘首页、企业官网反链证实的飞书单岗、无独立来源证明的假/第三方/海外链接、Provider 故障以及角色词与简历隔离。
- 最坏费用上限：三次公开 Search、六次公开 Fetch；不再为显示招聘入口消耗 4 次 Agent 模型调用或读取 20 条岗位说明。费用估计仍以 DeepSeek 实际计费为准。
- 前端保持简洁弹窗，链接点击直达企业页面；仅对岗位证据完整的记录显示“参考相关度”。

## 尚未解决/不能夸大

- **模拟回归通过并不代表实时招聘结果已通过实际联网验收**。仍须在受控 Preview 检索真实职业，核对搜索结果、真实官网链接和用户实际能够打开。
- “企业招聘入口”不保证该企业当前恰有用户所需职业、不会断言工作地一定在中国大陆；必须由用户在企业官网查看。
- 不自动投递、不索取企业私有 API、不绕过验证码及登录墙；真实岗位存续和用户资格以对应官网为准。
- Cloudflare Preview 部署完成前，不声称最新功能在预览网页可用。未经单独验收，不合并 `main` 或向正式站 `hhba.work` 开放用户。

## 下一步验收标准

**最小业务验收：** 给定“内容运营”等公开职业词，系统应输出实际可打开的企业招聘官网入口或具体单岗链接，且每条显示正确证据级别；至少3家不同企业作为首次目标，不以 10 条凑数。检查零分数欺骗和外链域名安全后，再由用户验收。

## V9.1 · 多职业方向公平发现与招聘渠道用语校正（2026-11-09）

- 修复原链接导航只使用第一个 `sanitizedJobIntent` 的缺陷。现在从既有简历职业意向、用户输入中最多选 3 个**已标准化的职业方向**，仍然严格最多 3 次公开 Search、6 次 Fetch、0 次额外模型调用。
- 当存在多个方向时按职业轮流分配 3 次 Search，企业公开招聘来源 Fetch 候选也按职业方向**轮询**，防止第一个方向耗尽读取额度。每个展示链接保留自己对应的职业词；单方向查询沿用原有 3 次搜索逻辑。
- 招聘官网与企业指向的共享 ATS 不混称：“直达官网”统一改为“打开招聘页”，并解释公开招聘导航**不是独立核实企业主体、岗位仍在招、学历/经验资格或中国大陆城市**的结论。真实岗位硬门槛核验仍只用于已核验岗位。
- 增加覆盖 3 个职业方向、企业来源读取、直达岗位角色归属、隐私和预算上限的自动化合约，并同步修改前端静态文案断言。
- 开发分支中的这次改动**不修改生产环境变量、Cloudflare 密钥、D1 用户数据、支付或正式站**，也不提高成本上限。需要 PR 自动化成功、预览可打开和真实招聘渠道人工抽查后才可以请求合并。

**仍然未完成的外部验收：** 未通过真实 DeepSeek 查询拿到至少 3 家互不重复、可打开且来源可信的企业招聘入口。自动化模拟测试无法证明真实在招职位，禁止宣称“正式上线”或将这种链接写成“已通过资格审核”。
