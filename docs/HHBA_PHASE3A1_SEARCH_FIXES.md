# Phase 3A.1 检索修复

检索流程为：认证/审核企业校验 → 每日配额事务 → 数据库授权过滤和结构化条件过滤 → 稳定 SQL 排序 → `OFFSET`/`LIMIT page_size+1` → 仅基于已授权字段生成匹配理由。

- 年限仅在档案明确填写且落在查询范围内时显示理由；不会由年龄或毕业年份推断。
- `candidate_ref` 是 32 位随机引用，新建投影生成，历史投影在 PostgreSQL 迁移中由 `md5(profile_id::text)` 回填。撤销授权后引用不能绕过检索授权。
- SQL 不再有 `limit(101)` 候选池截断。排序采用稳定、可解释的索引时间与档案 ID；当前版本不宣称 AI 相关性分数。

尚待后续专项：真实 PostgreSQL 上构造 300+ 候选人的分页无重复/无缺页基准测试；这是 READY 的剩余验证项，不应以现有 100/1000 Phase 3A 基准替代。
