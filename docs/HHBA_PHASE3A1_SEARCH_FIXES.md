# Phase 3A.1 检索修复

检索流程为：认证/审核企业校验 → 每日配额事务 → 数据库授权过滤和结构化条件过滤 → 稳定 SQL 排序 → `OFFSET`/`LIMIT page_size+1` → 仅基于已授权字段生成匹配理由。

- 年限仅在档案明确填写且落在查询范围内时显示理由；不会由年龄或毕业年份推断。
- `candidate_ref` 是 32 位随机引用，新建投影生成；`20261014_rotate_candidate_refs` 会将已存在的历史 `md5(profile_id::text)` 值轮换为随机引用，且不改动已经随机的稳定引用。撤销授权后引用不能绕过检索授权。
- SQL 不再有 `limit(101)` 候选池截断。排序采用稳定、可解释的索引时间与档案 ID；当前版本不宣称 AI 相关性分数。

本地回归以 305 个合成候选人遍历第 1–31 页，验证无重复、无遗漏、末页 `has_more=false`；真实 PostgreSQL 的 1,000 条合成候选人分页回归仍保留为数据库专项。
