# HHBA V1 Stage 2 — DeepSeek 搜索结果 → 私有企业知识库（待核验候选）

开发日期：2026-11-11。基础分支：`feature/hhba-v1-dual-classification-stage1-20261111`（PR #325）；本次为 S2 叠加分支。

## 目标与实际边界

**这是 HHBA 内部沉淀，不是面向用户的新页面、公开公司名录或自动投递系统。**

原有 DeepSeek Search 查询照旧，搜索、匹配、推荐、历史保存照旧。通过回调捕获这次 Search 已获取的公开职位 URL：
- **所有规范化后符合候选特征的 Search 命中**（单批最多 48）进入 `hhba_knowledge_sources`，即使没有进入推荐 Top10；没有可靠企业名则不猜企业身份。
- **实际匹配后选中的职位**（一批最多 10）提供“企业显示名称 + 招聘域名”的候选身份观察、具体职位名称、工作城市、岗位职能标签。不会把公司主营业务从岗位名称倒推出来。
- 只有开关 `HHBA_KNOWLEDGE_CAPTURE_ENABLED=1` + Cloudflare `waitUntil` + D1 绑定时才写数据库。开关默认关闭、且需先执行 Preview 迁移。
- 这条链**不发起额外 DeepSeek Search/Fetch/模型请求**，且捕获失败不会导致原岗位匹配失败。
- 所有数据都是公开搜索候选，**绝不自动成为可信企业白名单**，不宣称职位仍开放。
- 不存储用户身份、手机号、原始简历、脱敏简历正文、搜索查询、推荐评分、推荐理由、API Key 和任意原始网页内容。

## 数据模型与独立迁移

迁移：`apps/web/d1/0021_knowledge_capture_v1.sql`。选择 0021，以避开主线 0019 和其他未合并 PR 0020，仍需上线前核对真实迁移账本。

1. `hhba_knowledge_sources`：规范化招聘 URL、主机、来源类别、首次和最后发现时间、计数、审核状态/证明链接；初始永远 `PENDING`。
2. `hhba_knowledge_employer_observations`：AI 匹配输出的公司显示名 + 观察到的网址主机，仅作为企业身份候选；身份 `PENDING`；行业/业务标签 **不通过职位自行推断**，初始为空、等待正式企业介绍证据。
3. `hhba_knowledge_job_observations`：职位标题、明确中国大陆工作城市、岗位职能标签、企业候选和来源；初始 `SEARCH_CANDIDATE`，不是 `OPEN_CONFIRMED`。

去重使用服务器计算的 SHA-256 标识、D1 UNIQUE + `ON CONFLICT`，复查只更新观察计数和日期，绝不覆盖人工审核结果、已验证来源证明或其它字段。同名不同主机不自动归并，跨主机同公司后续人工/证据审定。

**注意**：`EMPLOYER_ATS` 是网址类型，不代表企业授权；泛 ATS 租户必须结合已审核的企业官网对该租户的显式链接证据。生产白名单和真实职位详情的核验在后续阶段实现。

## 内部数据流

```text
用户已授权简历匹配（现有逻辑，简历不写公共索引）
     |
原有 DeepSeek Search（不增加额外调用）
     +--- 所有规范化候选职位 URL ---> [公共来源候选库 PENDING]
     |
原有 Fetch + DeepSeek 排序
     +--- 已选职位的企业名、标题、城市 ---> [企业候选 PENDING + 职能标签]
                                               |
                                            [内部 D1]
                                               |
                 [后续: 企业官网发现 -> Fetch 企业介绍 -> 行业和业务多标签]
                 [后续: 官方站出站证据/ATS 租户核验 -> 白名单审核]
                 [后续: 具体岗位页面核验/更新/持续复用]
```

## 关键安全设计

- Search 页面结果当线索，而不是企业法定主体证据；只记录经现有网址安全筛选的 HTTPS 候选，拒绝第三方招聘板和危险 URL。
- 存储使用较严格的 URL 规范化：移除不认识的 query 参数（防止授权 token、邮箱泄露），仅保留常见无敏感职位 ID 参数。**实际用户点击的 URL 不做更改**。
- 对“公司名称”输入做敏感字段和长度约束；职业画像数据不会进入共享公司库。
- 不启用面向用户的读取接口；没有增加公开 D1 查询入口和页面。
- 回调由 `waitUntil` 处理；D1 不可用只记录固定告警标签，不记录搜索结果或内部源数据。
- 代码中的开关默认关闭，未做真实 DeepSeek 计费调用，未执行任何 D1 迁移，未部署预览或生产。
