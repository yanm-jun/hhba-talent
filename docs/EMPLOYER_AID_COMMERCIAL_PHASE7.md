# HHBA 模块 11–12｜企业发展帮扶与真实商务对接（开发预览）

**状态：隔离 GitHub 分支与 PostgreSQL 测试。尚未接入生产账户、买方同意库或订单凭证核验服务。默认全功能关闭。**

## 为什么要做
HHBA 的主要功能仍然是企业招聘和人才服务。辅助功能是在企业能提供可信的劳动保障和真实交付能力的情况下，通过 HHBA 的独立运营人员，主动帮助企业争取客户或供应链合作。**不是另外开发一个商品交易平台，不售卖高分，也不对企业承诺订单。**

## 本次实现
- 模块 11：`hhba_aid_applications_private`、`hhba_aid_events_private`、私有申请与业务证明关联；三类支持（客户引荐、上下游合作、信誉和品牌曝光）；申请进度、独立审核、拒绝或待补充、有效资格查询。
- 模块 12：`hhba_commercial_introductions_private`、`hhba_commercial_order_proofs_private`、`hhba_commercial_events_private`；匿名化潜在买方编码，独立审核的同意依据，受控商机阶段与独立审核订单凭证。
- `apps/api/aid_domain.py`：独立批准的帮扶政策 `AidPolicy(enabled=False)`；明确要求审核通过的阈值，不对所有企业设置默认门槛。企业可申请不等于自动满足资格。
- `apps/api/aid_store.py`：同企业证明材料核验，申请-审批与签约验证历史；状态机、跨组织隔离与隐私/权限检查。
- `apps/api/aid_routes.py`：公司成员、独立帮扶审核员、商务匹配员、买方同意复核员、成交凭证复核员五类不同授权；`workflow_enabled=False` 默认关闭，未接入生产验证服务不得启动。
- 前端 `/employer/aid/apply/`、`/employer/commercial/`、`/admin/employer-aid/`，连接原「HHBA 企业发展帮扶」和企业工作台，不改变「我要招人」主业务结构。
- PostgreSQL 真正测试角色冲突、重复申请、不同企业隔离、资格失效动态暂停、先同意后引荐、独立订单证据确认、历史不可删除。静态浏览器测试禁止实际运营按钮和假订单。

## 11 模块审核逻辑
1. 经认证的企业成员提出申请，需选择支持类型、描述既有产品/服务和交付能力，并引用本企业已经 verified/clean、`business_integrity` 类别的核验证据。
2. 当前公开信誉值和员工善待值，必须来自模块10有效的双人发布版本；且不低于经独立批准的帮助政策门槛（真实数值尚未批准，不得直接套测试阈值）。
3. 审核员必须来自独立平台岗位，不能是申请人、原证明材料核验人员或申请企业成员。提交申请不会自动审批，审核通过也不保证交付能力、客户兴趣或订单。
4. 员工善待证据失效、申诉未结、企业公开评分被暂停或不满足帮扶政策，企业端的有效申请状态将显示“暂停资格”，不再允许新建商业引荐。
5. 不把评分与资金或广告购买绑定；不因为付钱、浏览量或企业体量获得优先评级。

## 12 模块的真实状态机
- `identified`：平台工作人员仅在内部记录匿名化买方编号、行业、合作意向类别和最小必要事实。不显示在企业端。
- `consent_verified`：不同的买方知情同意核验员在独立检验证据后记录内部同意凭证编号。此时企业才可看到经同意披露的有限信息。
- `introduced`：商务匹配人员正式引荐。不得跳过同意阶段。
- `in_discussion`：进入双方洽谈。
- `not_pursued` / `closed`：停止或结束对接。**closed 不是成交。**
- `order-proof pending`：在有效帮扶资格下提交订单凭证索引，但不等于有订单。
- `order-proof verified`：另一名独立订单证据审核员审查确认，不能由引荐人、凭证提交者或同意审核人自己认定。
- 公司可查看的字段包括买方受限参考号、行业、合作类型、业务目的、阶段及独立订单凭证审核状态；没有 HR/员工反馈、买方个人联系电话、客户私有联系人名单。

## 当前没有做完、上线前不可回避的事
- 真正 HHBA 账户、经办人/组织权限、CSRF、审核人员任职关系、用户隐私/日志/加密与安全存储尚未接入。开发 API 工厂并不会让服务自动上线。
- 买方同意 **只保存受控凭证编号与独立审核人签认**；尚未接通真实授权文件库，独立审核员需要线下/受控渠道检验来源。没有这一步绝不能实际暴露任何买方信息。
- 订单凭证审核 **也是人工审核工作流**，不能自动证明合同真实、已付款、已履约，更不能作为对外公开交易额或平台业绩报表。合同及客户个人资料不进入静态数据库/UI。平台不能据此保证收入。
- 真实交付能力不能仅凭单一营业资质证明完全验证；正式审批需要独立行业检查、采购/交付清单及必要许可材料。
- 同一企业只能有一个指定帮扶类型的活跃申请，历史申请与审核事件保留。
- 当前交易数据是运营/企业私有的；没有公开奖励榜单、客户关系商城、可购买评分、公共商机搜索 API。
- 无需用户在前端填写 DeepSeek key，所有受保护的商业运营和账户仍由服务器统一管理。
- 静态 Pages `VITE_HHBA_AID_COMMERCIAL_API_ENABLED=0`；后端 `workflow_enabled=False`，`AidPolicy(enabled=False)` 且所有正式门槛未确定。
