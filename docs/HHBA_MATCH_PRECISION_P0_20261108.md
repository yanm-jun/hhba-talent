# HHBA 智能岗位匹配：P0 精准度整改与验收

日期：2026-11-08。开发 PR #290 以 #289（基础评分引擎）为基线；#289 以 #288（中国大陆统一搜索与弹窗）为基线。未经预览验收不合并 main、不发布 hhba.work。

## 核心改动

### 1. 保守、可溯源的专业工作年限

\`functions/_lib/resume-tenure.js\` 新增清晰工作经历区段的年月范围识别：支持 \`2022.07—2025.09\`、\`2023年7月 - 至今\` 等格式，累加不重叠的完整任职月份。只在工作区段内、日期附近有任职企业/职位文本时计入；教育、项目、兼职、实习、未来及无效日期不计。输出支持小数年（例如 3.2 年），不能将 2.9 年四舍五入为符合最低 3 年。不能识别的经历保留为「未知」，不猜测。

\`verifiedProfile\` 继续支持简历原文可以校验的明确「工作 3 年」声明；缺少明确年限时使用工作经历时间范围作为保守补充。模型不能以不在简历中的履历信息增加工作年限。

**局限**：只有年份没有月份、难以识别的排版、未标记“工作经历”的文本暂不自动换算；不能把“工作经历中的日期”视为已经完成对任职真实性的外部核验。需要未来提供用户确认途径。

### 2. 具体职业分类与层级

\`functions/_lib/match-ranking.js\` 将职业划分为更细的 Python/后端、前端、全栈、测试开发、运维、数据分析、数据开发、算法/数据科学、销售、设计等类别。

- **职业方向不符**：Python 开发意向的用户，即使会 Python/SQL，也不能因工具相同就高分匹配测试开发、数据分析等明显不同方向。可转型相邻职业保留受控的较弱关联。
- **职位级别**：识别初级、资深、负责人、总监、实习等级，并依据已证明工作年限进行*软性降分*。只有官方招聘要求明示的最低年限或学历能成为硬性资格门槛，不能根据“Senior”几个字直接编造必须 5 年经验。
- **职业方向无证据**：职位分类未知、只有技能重合的候选不能高分挤进前列；最多 55 分，记录 \`score_adjustment\` 以解释上限。不把分数称为录用成功率。

### 3. 不让旧规则先截断

\`resume-match-core.js\` 在后端授权的候选池模式中，不再先用旧关键词算法截到 60 条，也不先用旧规则按公司/城市去重。所有通过同版官方 JD 哈希核验的职位先走 V2 职业/资格评分，最多 1,200 条按 V2 排序进入 \`domestic-match-fusion.js\`，再综合外部已验证岗位跨来源去重并输出 Top 10。

仍然没有编造职位，也没有解除中国大陆实际工作地点、学历、年限等硬条件；1,200 是服务器资源安全上限，**不是全中国企业覆盖数**。

## 自动化与验收

- 工作年限测试覆盖：12 月边界、当前在职、交叉任职不重复、空档不填充、实习/项目/教育不计数、未来日期拒绝、模型错误声明拒绝。
- 职业测试覆盖：Python 开发 vs 测试开发/数据分析/运维，资深/实习识别、学历和年限硬门槛、小数年。
- 72 个同版已审核职位验证：候选不提前截为 60，最终跨企业 Top 10 无重复。
- 两套 CI 覆盖新模块的语法、匹配/搜索回归、TypeScript/Vite 构建。**自动化通过并不证明真实 DeepSeek 搜索命中率或浏览器 UI 已验收。**

## 下一阶段建议

1. DeepSeek 搜索覆盖：现有 Search/Fetch 的官方接口已可用，但安全直链解析仍只覆盖少量已适配企业。扩展更多国内真实企业的**官网详情核验适配器**，提高召回；不因模型搜索摘要包含公司名就当作招聘事实。
2. 技能细化：区分职位的必备技能、加分技能与不要求；识别技能名称同义词，不仅依赖关键字重合。
3. 真实样本质量评估：用涵盖不同职业、工作年限的授权测试简历，统计 Top 10 人工相关率和硬条件误入率，不能把自动单元测试通过当作真实推荐准确率。
4. Cloudflare 预览构建、登录态真实简历匹配、手机端详情与官方链接需人工验收后，才讨论合并与正式部署。

## 隐私与学习边界

不新增用户点击、投递、收藏跟踪或训练数据；未来权重调整仍需匿名汇总、离线对照和人工审核，不能通过用户浏览器直接改算法。
