# HHBA · 企业资料库（Company Registry）操作规程

## 目标
招聘市场任何一个拥有近期可验证官方职位的企业，均可从 Logo/名称打开其专属 HHBA 页面。
**页面存在 ≠ 企业背景完成审核**。真正的企业介绍只有在有可靠来源支持并复核后才能显示。

## 企业唯一身份
企业的初始 ID 由职位来源的 `platform + source + company` 精确组成，并编码为 URL-safe Base64。
这种方式避免将名称相近的不同雇主错误合并。同一企业分布于多个 ATS 来源的合并，以及集团与子公司归属，必须另有证据并经人工核对。
新增职位后目录自动由当前官方索引生成；不再添加 React 页面或静态企业列表。

## 资料状态
- `NEEDS_REVIEW`: 企业名称来自真实招聘来源；仅展示经审核岗位与真实原始职位链接；企业官网、行业、成立时间、产品、Logo 和发展历程留待核实。
- `VERIFIED`: 独立提供有效出处，按字段核实、翻译并提交 `apps/web/src/data/reviewedEmployers.json` 的记录；前端从数据文件读取，不更改组件代码。
- 若官方职位索引与审计版本不一致、该企业所有职位过期或不合格，隐藏职位并按源数据不可用提示，不伪造工作机会。

## 使用离线工具导出审核队列
以同一次同步产生的 `jobs.json`、`job-sync-status.json` 为输入：

```bash
node apps/web/scripts/export-company-review-queue.mjs \
  jobs.json job-sync-status.json company-review-queue.json
```

输出仅包含观察到的企业身份、来源、可核验官方职位链接、职位数和 `NEEDS_REVIEW`，不包含假企业网站、描述、成立年份或 Logo。输出用新文件创建，绝不覆盖用户已有资料。人工作业可以按职位最多的企业优先处理。

## 人工编辑/核实规则
1. 通过企业官方域名找到“关于我们”、产品、招聘和历史页面。必要时核对监管公开登记、权威公司披露或官方新闻稿。
2. 用事实依据分别审核企业全称、法律实体/集团关系、行业、总部、成立时间、主要产品、发展节点；对无法核实的字段不要猜。
3. 中文和英文独立校对，不允许照抄不可授权的长段原文；撰写 HHBA 自己的简明介绍。
4. 真实品牌文件通过公司官网/品牌资源包取得，记录 URL 与 SHA-256，确认许可；不得用搜索结果、生成图片、相似字标冒充官方。
5. 每条 `VERIFIED` 记录必须有至少两条真实 HTTPS 参考来源、更新时间、经过核实的岗位板主体 identity。推荐每段主要事实附上可以定位的出处和核验记录。
6. 通过 `reviewedCompanyEditorial.ts` 的数据校验、TypeScript 构建、浏览器真机验收，再发布。企业自述不等于 HHBA 招聘授权。
7. 定期复核，职位随官方同步更新；企业资料变更则生成新的审核版本。

## 用户体验验收
- 所有身份可识别的岗位卡片：点击企业名字或通用 Logo → 独立企业资料页；点击职位名称/查看岗位 → 原职位完整 JD。
- 已审核的 OpenAI、Anthropic（Claude 图标）、SpaceX 仍走原有深度介绍页面。
- 普通企业：名称与近期已核验职位直接可用；尚未审核的背景和产品明确标记待完善，无自绘 Logo。
- `/companies` 为可搜索的企业目录；`/companies/id/<ID>` 直接刷新可用。
- 从岗位详情或首页进入公司页，返回按钮能恢复原来页面的筛选与滚动位置。
- 未经证实的企业身份不应拥有公开“已验证企业信息”状态。
