## D1 实施约束

- **正式绑定**：`HHBA_PNVS_AUTH_DB`，不可删除或覆盖原注册、会话和短信数据。
- **预览绑定**：使用独立的空白 PNVS D1（不是生产库）。已在预览数据库执行认证基础迁移 `0004_hhba_auth.sql` 和新增 `0006_real_candidate_workspace.sql`。不迁移真人资料到预览环境。
- **生产迁移**：暂未执行。代码合并前要做备份、核实当前生产库表及绑定，并在适当发布窗口执行 `0006_real_candidate_workspace.sql`。新表使用 `CREATE TABLE IF NOT EXISTS`，不更改原 `hhba_auth_users`。
- 生产迁移成功且 API 抽样验收后才能启用个人资料与收藏。若 DB 连接缺失或新表不可用，服务端返回明确错误，不可回退到浏览器模拟账户。
- **不迁移匿名设备收藏到真实账户**：不应自动将一个设备的历史收藏认领给某个手机号，否则共享设备会引发隐私泄露。

## 验收用例（不得使用真实账号数据冒充测试）

1. 新 PNVS 账号登录后进入原版工作台，刷新页面仍保持授权，退出后 session 失效。
2. A、B 两个独立测试账号：A 保存的资料、偏好、职位，B 读取均为空或自己的数据；B 无法删除 A 的收藏。
3. 非登录/伪造 token / 跨站请求，不允许写入账号数据。
4. 未连接的简历/申请显示“未接入”，不能出现演示文件或伪造投递状态。
5. 同一真实账号跨两个浏览器登录，读取相同服务器端资料与收藏。
6. 原管理员后台只允许 Access 白名单；总注册人数来自生产 D1，DAU/MAU 数据未有明确口径前保持未接入。
7. GitHub Pages 静态站不能伪装有真实账户 API；正式 Cloudflare 与预览 Cloudflare 不共享认证数据库。
8. 所有变更先在 PR、CI 和隔离预览环境检查，人工验收后再合并 `main`，不得在尚未备份时变更生产个人数据。

## 隐私与合规待办

实名认证与登录仅为账号管理使用；简历属于高度敏感的求职资料，必须先明确存储位置、加密、访问权限、保留期限、撤回/注销/删除路径及公开范围。用户协议与隐私政策的正式文案须核实运营主体、联系渠道、数据处理者和短信供应商，不得编造运营信息或用示范文本冒充已生效的法务文件。

本单不是八项全完结声明，按可验证的后端能力逐步更新每项状态。
