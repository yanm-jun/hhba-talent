# RISKS_AND_MANUAL —— 必须由账号所有者完成的人工事项

原则：以下事项涉及付费、资质、生产授权或账号安全，助手/代码无法代办。
每项给出入口与卡点；未完成前，对应能力只能停在「代码完成」状态，不得声称上线。
其余不依赖这些事项的开发已在本代码包内完成，不因等待而停工。

---

## 1. 阿里云短信签名与模板审核（阻塞：真实短信发送）

- **要做什么**：为 HHBA 申请短信签名（如「HHBA」或公司主体简称）+ 验证码模板
  （内容含 `${code}` 变量，与 `sms-provider.ts` 的 templateParam 约定一致）。
- **入口**：阿里云控制台 → 短信服务 → 国内消息 → 签名管理 / 模板管理 → 添加签名/模板。
  需要企业营业执照、经办人信息；签名审核通常 2 小时–2 天，模板另审。
- **卡点**：
  - 签名须与主体资质一致，个人账号无法申请企业签名；
  - **历史欠费先清**：该阿里云账号 2026-10-09 曾因欠费（余额 -1.35 元）被暂停短信服务，
    控制台「费用与成本」确认余额为正、短信服务状态正常后再提交审核；
  - 审核结果（签名名称、模板 CODE）填入服务器 `.env.production` 的
    `ALIYUN_SMS_SIGN_NAME` / `ALIYUN_SMS_TEMPLATE_CODE`，不要发到聊天/GitHub。
- **可先行**：适配器、mock 联调、错误码映射均已完成（本包 Phase 2），审核通过后改
  `HHBA_SMS_PROVIDER=aliyun` 即可进入真实发送验证。

## 2. 阿里云 AccessKey 创建（阻塞：短信 SDK 调用；有免密替代待核）

- **要做什么**：二选一——
  - A. RAM 控制台 → 用户 → 创建用户（仅编程访问）→ 授予 `AliyunDysmsFullAccess`
    （或最小化的 SendSms 自定义策略）→ 创建 AccessKey，填入 `.env.production`；
  - B. **优先核查**：目标 ECS 已绑短信专用 RAM 角色 `OpenNestSmsAuthEcsRole`
    （原 HAAM 用）。若其策略覆盖 Dysms SendSms 且允许 HHBA 复用，可改用实例元数据
    免密调用，服务器上不落任何长期密钥（更安全）。需所有者在 RAM 控制台打开该角色
    确认策略范围，或授权后由部署方只读核查。
- **卡点**：主账号 AccessKey 禁止使用；密钥只进服务器 600 权限 env 文件，不进 Git、不进聊天。

## 3. Railway 卷导出授权（阻塞：生产数据迁移）

- **要做什么**：在 Railway 控制台确认 `hhba-web` 服务的 Volume（`/sync-state`）内容并导出：
  `hhba-engagement.sqlite`、`hhba-saved.sqlite`、`overseas-jd.sqlite`、`public-index/`。
  Railway 无一键下载卷文件时，可用其 CLI/临时服务挂载同卷后跑本包 `backup-sqlite.sh` 再取回产物。
- **入口**：Railway 项目「HHBA Recruitment Marketplace」→ hhba-web → Settings/Volumes；
  或本机 `railway login` 后 CLI 操作（登录须所有者本人完成）。
- **卡点**：导出的是含匿名访客哈希与设备收藏的生产数据，只能走私有通道传输，
  禁止贴公开链接；迁移完成前 Railway 服务与卷**不得删除**（回滚命脉）。

## 4. ECS 选型与处置（已有决定，待所有者确认执行窗口）

- **现状（2026-10-21 所有者改令）**：现有 ECS（123.57.230.17，华北2北京，2 核/约 1.6G 内存）
  上的 HAAM 内容全部清掉改放 HHBA，顺序为「先完整备份并校验 → 再清 → 再部署 HHBA」；
  登录走阿里云控制台 Workbench（沙箱直连 SSH 不通）。
- **待所有者确认**：
  - 清理窗口与 HAAM 旧备份（/root/backups 一带）的最终去留；
  - 内存约 1.6G 跑 hhba-web + PostgreSQL 17 + Caddy 偏紧：确认是否升配（建议 ≥4G）
    或接受先小规格试运行、PG 参数调小（shared_buffers 等）的降级方案；
  - 安全组放行 80/443、关闭不必要的入站端口，由所有者在控制台操作或授权代操作。
- **卡点**：未完成第 3 项（Railway 数据备份就位）前，不得先清这台机器上与迁移有关的任何中转数据。

## 5. ICP 备案（阻塞：中国内地正式公开上线）

- **要做什么**：确认 hhba.com.cn 的备案主体与状态（该域名现解析到的服务在跑旧 HHBA，
  备案情况须在阿里云备案系统/工信部系统复核）；若换主体或新增服务，按阿里云
  「ICP备案」流程提交（主体证件、域名证书、核验单/幕布拍照等，周期通常 1–3 周）。
- **卡点**：新 ECS 若与备案接入商不一致需做「接入备案」；备案未完成前，
  只能用 IP/临时域名做测试环境验收，不得宣称内地正式上线完成。

## 6. 域名解析切换（最后一步，所有者操作）

- **现状（须复核，沙箱 DNS 结果不一致）**：hhba.com.cn 与 www.hhba.com.cn 的 HTTPS 目前均返回 200
  （应是旧 HHBA 生产在跑）；hhba.cn 的 HTTP 跳到了无关域名（疑似闲置或被转发）。
  切换前须在阿里云云解析 DNS 控制台逐条核对现有 A/CNAME 记录并截图留档。
- **切换步骤（验收全过后）**：先把 TTL 改小（300s）→ 测试环境用 hosts/临时子域
  （如 test.hhba.com.cn）全量验收 → 正式记录指向新 ECS → 观察 24h → 异常按
  原记录值回滚（Railway 仍在运行，回滚即改回解析）。
- **卡点**：hhba.cn 的异常跳转先查清是所有者自己的转发还是域名被占用/过期，
  未查清前不要把 hhba.cn 当作备用回滚域名。
