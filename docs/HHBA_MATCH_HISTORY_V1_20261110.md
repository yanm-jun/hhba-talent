# HHBA 求职者简历与 AI 匹配历史 V1（2026-11-10）

## 产品验收链路
1. 首页 **我要应聘**：未登录 → /candidate/login?next=%2Fcandidate%2Fmatch → 登录/注册成功后进入 /candidate/match。已登录直接进入 AI 上传与匹配页。招聘方入口保持不变。
2. 简历 AI 分析：复用当前 PDF/DOCX 本地提取文本与独立 DeepSeek 同意，按用户主动请求搜索中国大陆企业招聘网站和专属 ATS，禁止第三方公开招聘平台链接、模拟岗位或虚构分数。
3. **我的简历**：用户完成匹配后可单独勾选私有存储授权并主动保存原始文件到原有 Cloudflare R2。R2 文件不公开，私有数据库校验用户归属，最大 3 MB、单账户最多3份；不因为匹配自动保存文件。
4. **匹配历史**：POST /api/match-native/resume 服务端完成搜索和匹配后，保存最多10条真实企业岗位链接的私有推荐快照。保存简历后，用户可单独将历史记录关联到同一账户的简历。不能通过浏览器提交任意历史岗位来伪造求职申请。
5. 「求职申请」工作台卡和侧栏名称改成「AI 匹配历史」/「匹配历史」，展示真实历史次数；历史明细可以查看当时职位、城市、适配分、原始链接、理由并删除，仍在招状态需回到招聘官网确认。
6. 与此前的历史运行比较，如果出现从未向该账户推荐过的公司职位**原始 URL**，可以标注「此前未推荐过的岗位」。同一职位模型分数波动不是新的岗位，历史不是已经投递/面试/录用记录。

## 安全与隐私边界

- API \`GET /api/match-history\`, \`GET /api/match-history/:id\`, \`DELETE /api/match-history/:id\`, \`POST /api/match-history/:id/link\`，全部 Bearer 验证和用户角色与行级手机号限定，写操作严格同源检查。
- 所有自动创建历史记录只由已经验证会话的 \`/api/match-native/resume\` 在模型输出成功后写入；不允许从前端 POST 任意岗位。推荐结果由现有 Search-first 服务取得，必须是允许的企业域名/企业专属 ATS HTTPS 具体职位链接。
- 用户本人可删除匹配历史，删除不会删除原始 R2 简历；删除原始简历不会删除历史推荐快照，但是历史中保存的简历版本无法再次载入。
- 历史数据库迁移缺失或出错时，AI 匹配仍尽量返回真实结果，但前端必须显示「尚未保存」警告，不得伪称保存成功。
- AI 原始文本分享同意与 R2 原始文件私有存储同意继续独立，未新增统计授权弹窗。
- 遵守「仅给用户端真实中国大陆岗位，不使用 BOSS/智联/前程无忧/猎聘等公开招聘平台」定版规则。

## 新岗位提醒的阶段边界

**V1 只在用户主动再次匹配后计算真实新链接数量**，并保留以后进行新机会提醒的结构化数据基础。未提供后台定时任务、邮件/短信推送或「比以前更容易拿到 Offer」的声称。未来如需后台自动监测，需要另行加入用户自主开启/关闭、频率、费用和有效性验证，同时完成具体验收后才能对外宣传。

## 验收

- GitHub PR #315 必须通过 CI（包括主 Web 构建、真实账户安全、私有 R2、登录、旧工作台和新历史契约）。

- 验收只在 Preview 上进行，不得改动 \`hhba.work\` 或 Production D1 数据。
