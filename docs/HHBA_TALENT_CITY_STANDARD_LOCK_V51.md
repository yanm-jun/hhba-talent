# HHBA 人才政策「锁定模板」开发规范 V5.1
版本：2026-10-30　|　仓库：yanm-jun/hhba-talent　|　主线：main

## 1. 设计冻结
每座城市使用以下三种公用渲染器：
- \`components/talent/UnifiedPolicyList.tsx\` — 分类筛选、简洁卡片、金额突出、历史政策独立分组。
- \`components/talent/UnifiedPolicyGuide.tsx\` — 六大内容区域：待遇、资格、每步为什么/如何做/完成标志、材料自查、FAQ、官方依据与联系渠道。步骤数量应忠于官方真实程序，不能强制填六步。
- \`components/talent/UnifiedTalentRecordDetail.tsx\` — 旧政策与住房统一基础详情；资料不全必须标记待核验，不能凭模板虚构材料或办事入口。

禁止再复制 \`Talent<City>GuidePreview.tsx\` 给下一座城市。未来只能增加政策数据、配置和共享路由；需要改视觉时只修改公共组件，同时回归验证已验收城市。现有济南、青岛兼容配置保留。

## 2. 一条数据的最低真实性
政策：真实原文URL和发布日期、正确适用范围、学历/就业/参保/住房/家庭条件、资金发放主体、分步申报过程、材料出处、实际申报入口或**明确未公布**、官方或监管部门及资料核验日期、历史批次状态。
住房：真实项目地址、项目与批次房源总量（不等于实时空房）、不同户型/租金、公示与申报时限、家庭住房限制、真实选房签约步骤、公开咨询方式或注明未公开。
官方原文与申报平台必须分别记录；官网首页不自动视为申请入口。第三方报道、学校转载绝不可冒充政策主管部门的一手文件。

## 3. 完整度等级和升级规则
- **A：完整指南**。必须在 \`CERTIFIED_TALENT_GUIDES\` 有正式条目、对应实际页面和官方证据、并通过CI核对申请分支、完整步骤和FAQ。仅仅数据有几条 \`applicationSteps\` 不会自动升级。到期则降C。
- **B：基础资料**。仍有明确未核实部分，不可显示“完整办事指南”。
- **C：历史/已截止**。即使原来A级，也不可作为当前可申请推荐；按日期自动降级。
- **D：来源不可确认**。不能作为可申领依据推荐。
本等级衡量**资料建设程度**，不代表申请人是否有资格或已经审核通过。

## 4. 城市最终验收机制
仅有系统内明确批准的城市，且该城所有未过期政策与住房均为A级，才可以标为「整城完成」。截至此规范版本，**没有任何城市获得整城完成认证**，既有95条原始资料仍可浏览，不擅自隐去。
开发新城时，必须先准备官方政策、整理到共用数据模型、通过统一列表和详细指南核验、核查手机与电脑端，再交付GitHub静态预览。用户人工确认后，才可考虑批准整城状态。
CI锁定2026-10-30现有71条政策+24条住房的ID；不能删除旧资料，也不能悄悄复用ID覆盖另一政策。所有新增政策要求至少4个独立、实际可操作的办理环节和至少3种资料，住房有真实申请/选房步骤；**这是数据最少项，不等于A级，仍必须有独立完整指南**。没有公布的条件只标待核验，绝不凭空编造。

## 5. 不可变流程与部署
1. 在 \`main\` 维护官方证据与数据，统一组件不产生城市视觉分叉。
2. 执行政策和住房专项数据核验，分档记录未完成事项。
3. 执行 \`scripts/test-talent-city-contract-v51.mjs\` 与其他已有招聘回归检查，必须全绿。
4. 发布 GitHub Pages 真实可点击版本，用户亲自验收。
5. 未经单独授权 **不得更新阿里云正式环境**。
