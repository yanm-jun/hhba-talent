# HHBA 国内岗位 V2 重建标准（用户确认的长期产品规则）

更新：2026-10-29 · 优先级：产品架构基线

## 核心决策

1. 海外精选 **10 家企业 × 每家 10 条 = 100 条** 岗位资料完整保留。ID、中文详情、样式、官方链接、历史状态不得因国内改造而损坏。
2. 国内岗位**从旧库重新建立**。旧国内卡片、招聘项目、招聘渠道占位不能继续充当“招聘岗位”；旧 1.5 万混合快照不再作为 V2 公共岗位市场数据源。
3. **绝不永久销毁可复用资产。** 以前的国内企业档案、岗位来源记录、Logo、已生成的独立办公/行业示意照片都作为备份保留在代码库。无须重复制作正确照片；品牌归属错误的图片不得使用。
4. 国内岗位按**一家企业一家企业**核实、整理、验收。华域视觉、华安证券及此前同期制作的所有国内企业都必须按新标准重新过一遍，不能仅补按钮或免责声明。
5. **一个市场、一套卡片、一套详情。** 国内和海外岗位共用搜索、列表卡片、站内岗位详情、收藏与注册登录及官方投递校验。具体交互有后端依赖时，不得把静态预览冒充真实账户功能。
6. 国内企业资料页只保留以下四块，顺序固定：
   - 第一：真实企业 Logo + 企业名称 + 两张已确认归属的独立办公/行业图片；AI 生成场景标注“AI 示意”。
   - 第二：适合的专业背景；专业选择可关联筛选下面有证据的岗位。
   - 第三：招聘岗位（必须是具体职位；有来源、工作地点、要求和站内详情，官方渠道作为岗位的最终入口）。
   - 第四：主要业务与专业服务（紧凑卡片，按需展开）。
   删除独立的“关于企业”长文、“发展与重要节点”、“信息来源”、冗长的免责声明、只有官网入口但没有岗位的假卡片。
7. **证据优先。** 招聘官网不等于在招职位。明确区分“具体职位历史来源”“当前开放投递”“招聘项目”和“仅有官网入口”；不能虚构学历、城市、岗位职责或当前申请状态。
8. **固定开发和部署流程：** Codex/开发环境先做可访问可点击的 GitHub Pages 静态验收版；用户亲自验收后才允许 Muse 部署阿里云正式环境；禁止未经确认修改正式服务器。

## 分阶段实施

- Phase 1：对公开岗位市场启用国内 V2 白名单，只读取原海外 100 条 + 审核通过的国内岗位；旧国内记录退出公开列表，但保留源文件。上线静态预览。
- Phase 2：施耐德电气作为第一家已具备具体职位链接和图片的技术验证企业。逐条完善职位 JD 和专业核对。
- Phase 3：逐家重新制作国内企业：包括此前已做的毕马威、华域视觉、华安证券等。每家先核实岗位事实，再接照片、专业、业务模块；验收后才标记完成。
- Phase 4：统一检索、按专业筛选、站内岗位详情、登录后官方投递、收藏和数据指标，再进行跨端验收。

## 完成定义

一家国内企业只有当 Logo 和照片归属正确、具体岗位可追溯且页面可阅读、专业信息有依据、招聘入口不绕过 HHBA 登录、手机电脑排版一致、GitHub Pages 测试通过，并得到用户验收确认，才允许标记“已完成”。

此文件是**项目长期约定**，不是用户对任何具体企业已验收的证明。
