# HHBA Phase 3A.1 前端体验审查

日期：2026-10-14。分支：`feat/phase3a1-search-hardening`。基线提交：`570bb9e`。

## 审查范围与真实结论

已实际检查求职端的 `/candidate/review`、`/candidate/profile`、公开名片，以及企业端既有需求页面的源码。个人端在本轮前存在三个会造成误解的问题：职业字段全部堆叠在一个密集表单中；名片页只用“私密/公开”表达状态；“搜索引擎收录”在公开分享关闭时被禁用，用户不能主动撤销已有授权。

企业端现有自然语言需求输入与草稿流没有进行重做；其信息架构仍保持“先描述需求，再保存草稿”的最小流程。本轮没有添加人才结果或 Phase 3B/3C 功能。

## 已落实的体验原则

- 能力核对按“职业方向、核心技能、地区/年限/合作方式、可提供服务”分组；工作年限有 0–80 的明确校验和就地错误提示。
- 名片页同时呈现档案确认、企业检索、公开分享、搜索引擎收录四个独立状态，避免把“已确认”误说成“已公开”。
- 企业可见范围使用后端 `/api/v1/me/profile/enterprise-preview` 返回的投影字段；前端不拼接原始简历或联系方式。
- 每项授权旁显示作用范围与当前状态。搜索引擎授权始终可撤销；公开分享关闭时它不生效，但不会被 UI 锁死。
- 发布确认和撤回确认均明确写出：公开分享与企业检索相互独立。
- 新样式在窄屏下将状态格、预览字段和选择项降为单列，勾选项保持可触控的整块标签。

## 未完成的验收

没有在本轮重新跑完上传、Worker 解析、企业草稿的全新浏览器会话；也没有取得 705×357 与 390×844 的持久化浏览器截图。因此本次 UX 最终状态仍为 `PARTIAL`，不能仅因求职端发布/撤回闭环通过而标记 READY。
