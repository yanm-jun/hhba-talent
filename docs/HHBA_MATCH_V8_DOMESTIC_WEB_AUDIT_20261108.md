## 此轮 V8 续接实做

- `publicJobLink`：额外识别有可证明单岗结构的职业 slug、`/job/view/99` 和公开 ATS 带 `postIdEnc` 的岗位详情；保留 HTTPS、无用户名密码/危险参数、页内结构完整核验。普通列表页和任意查询参数继续拒绝。
- `readPublicJob`：岗位页标题“加入企业品牌”可提供来自 **已 Fetch 职位页** 的公司名称线索，绝不从模型猜测或企业首页反向填写；避免“社会招聘”“全国 [切换]”之类导航误判。
- 支持“工作要求”类岗位资格小标题和“职位详情 - 某某岗位”的页标题；同时拒绝“工作要求：待定/暂无”等并不明确的资格条件。
- `hasApplyEntry`：识别“投递此职位”等等价动作，不将资讯列表、企业官网普通导航当作投递按钮。
- 新增实际国内网页结构的合约场景以及相应负例；岗位地点、学历经验、必要证书、强制技能和公司官网来源的硬门槛一律保留。
- 模型/Search/Fetch 单次预算仍为 **4/8/20**。根据实际请求与 token 计量，失败时 `complete=false`；不写入简历正文、网页正文或搜索关键词到费用账单。
- V8 分支最新核心提交 `8d93b80c`；GitHub Actions `42492197583`：**175/175** 单测通过，前端生产构建和 HTTPS 预览安全冒烟通过；同次运行其它两组工作流也通过。

## 上线仍需的关键验证

1. 在测试隔离环境、无真实求职者资料的前提下，重新进行 DeepSeek V4 Pro + Search + Fetch **受控端到端**。新版本必须比过去的 0 个可信岗位有可复核的正例，也必须有拒绝原因和失败请求成本。
