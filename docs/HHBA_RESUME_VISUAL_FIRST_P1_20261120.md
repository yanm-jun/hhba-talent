# HHBA 视觉优先原件编辑｜P1 实现与验收（2026-11-20）

> 独立 PR #405 的增量研发记录。当前为 Preview-only / Draft，不应宣传为“任意 PDF/Word 可无损原位编辑”。

## 产品方向

用户上传的是**原始简历**。平台负责在后台理解页面布局，前端只展示文件与必要的修改控件，不展示模型、OCR、解析比例等技术流水线。原件与编辑副本必须分离。

## 本次已落地

1. 私人简历库上传后直接显示原文件预览；已有文件新增「查看」入口。PDF 通过固定版本的 PDF.js 在浏览器本地把**实际保存的原始 PDF**绘制到 canvas，不从提取文本重新排版；只通过账户授权的原有附件下载 API 获取 bytes，不使用公开 R2 链接。
2. DOCX 当前仅展示本地提取的文字校对预览，并明确声明不能保证原始字体、表格、双栏样式；禁止把该视图称作 Word 原件高保真渲染。
3. 新增服务器接口 `/api/resume-layout`。仅当候选人登录、用户主动发送 `consent_ai_vision:true`、源文件 ID 属于该账户、Preview/Production 独立功能开关已开启、数据库与提供商已配置时，才从私有 R2 读取原 PDF。服务器以 OpenAI Responses API 的 PDF `input_file` 高细节模式进行多模态理解，向模型请求页面区域、文本、分栏和 0–1000 相对坐标；未持有外部可公开访问的文档 URL。
4. 标准化结果含页面、段落类型、候选文字、相对框、置信度和“待校验”标记；所有来源模型的坐标均视为**未验证**，绝不直接授权写回 PDF。
5. 已核验的模型结果缓存在同一私有 R2 桶，按原件存储 key + 原件 SHA-256 隔离。候选人再次确认使用同份简历时复用缓存，不重复调用模型。删除原件时一起清理对应缓存。
6. 新增 D1 独立每日调用尝试账本 `0025_resume_visual_attempts.sql`；单账户每日最多两次未缓存尝试（模型失败也计入），规避无限重试付费。**只在 Preview D1** 执行了增量迁移并确认表、索引存在；生产 D1 未改动。
7. 浏览器 QA 使用纯合成 PDF 验证 PDF.js 可绘制原始页面（含中文网页界面），同时保持原有 AI 原位建议、版本保存、A4 PDF/Word 导出回归。服务器契约测试验证了显式授权、相同源站、候选人身份、文件属主、私有缓存和请求上限。

## 默认关闭与接入边界

- `HHBA_RESUME_VISION_ENABLED=1`：独立开关，**目前没有开启**。
- `HHBA_AI_OPENAI_API_KEY`：服务端密钥，必须在 Cloudflare 的加密环境绑定中配置，禁止提交代码或在浏览器泄露。
- `HHBA_RESUME_VISION_MODEL`：可选，默认 `gpt-4.1-mini`；选择时应再次核实当前价格、视觉 PDF 支持及 API 权限。
- Preview 页面已绑定独立 R2 和隔离 D1；**没有发送任何真实候选人 PDF 给外部视觉模型**。
- API 使用 OpenAI PDF 内嵌页面视觉输入；当前 DeepSeek 的图像接口不等于 DOCX 原版式渲染器，不能无转换直接兑现同样的 PDF/Word 保真效果。
- 视觉模型输入会包含未必能完全脱敏的文件原件，因此必须独立征得清晰的第三方模型共享授权。响应使用 `store:false`，但仍要依据正式隐私说明、服务商政策和合法跨境传输安排核实完整数据处理链路。
- 模型生成的结构化缓存可能含个人信息，必须与源文件同级保密、按删除操作清理。

## 明确尚未实现

- **视觉识别已接入原件页的段落定位、人工修改及私有草稿保存。** 但尚未接入整个岗位定向优化后的最终导出链路；服务开关未开启，尚未实测真实模型完整响应，不能宣称线上可用。
- Word 原件像素级预览需要后端可信 DOCX→页面转换器（自托管优先），不应借助公开 Office 在线预览 URL 泄露私有简历。
- 视觉框仍需与原始 PDF.js 文本对象/坐标进行一致性校验，才允许把用户确认的修改关联到具体段落；识别低置信或多栏错序时必须阻止自动替换。
- 原 PDF 中替换文字需要真实排版和重流引擎；当前版本仅有基于结构化文本的 PDF/DOCX 标准版导出，不保证保持复杂原始设计。不能把 canvas 上覆盖文字视为已修改原文件。
- 真实登录→R2 上传→外部视觉服务→区域校验→原位修改→原样导出 PDF/Word 的端到端闭环尚未完成。

## P5｜保存修改后生成可查看的独立 PDF 预览稿（2026-11-20）

**这是独立页面图像的 PDF 预览副本，不是可检索的最终求职 PDF，也不是原始 PDF 内容流的无损修改。**

- `src/services/resumePdfReviewCopy.mjs`：原始 PDF 通过本地 PDF.js 逐页重新渲染，以 JPEG 图片逐页生成标准 PDF-1.4；源文件始终保留，不修改或上传额外文件给第三方。每页保持原始页面的宽高比、页码数量和视觉布局，后续阶段再引入可检索文本的布局重写。
- 导出时重新依据原件文字对象、页面位置、单行限制、文字实际尺寸和白底像素四点核查每一条**用户已确认的修改**；每一项必须可安全放回原位置，否则整个导出失败，绝不把一部分修改遗漏掉仍宣称成功。
- 原件只在私有已授权会话中获取，导出发生在用户本地浏览器。源页面经过完整栅格化，不把白色覆盖下的旧文字对象夹带到新 PDF，因此导出文本不可选、不可检索。文件名明确包含「修改预览稿」，前端提示「仅供检查效果，文字无法选中，不建议直接投递」。
- 单文件目前限制 12 页、合计 JPEG 28 MB，以控制手机浏览器的内存和处理负担；原文件依旧保存在用户私有存储。
- `resume-pdf-review-copy.contract.test.mjs`：校验 PDF-1.4 结构、JPEG 图像 XObject、交叉引用、双页结构、错误图片/尺寸和输入处理；`resume-browser.qa.mjs`：真实 Chromium 执行短文保存→下载修改预览稿→通过 PDF.js 重新读取确认 1 页及不可搜索文字，再核验长文字被阻止生成而非部分漏改。
- QA run `44581774882` 产生 `edited-original-review.pdf`，本地使用 Poppler `pdfinfo` 和 `pdftoppm` 再次验证文件正确渲染，页面内有 `EDITED RESUME VIEW` 且 `pdftotext` 无可提取文字。9/9 GitHub CI 全成功，最终 SHA `de379b0cfcf22ac353d0aeb12633b55e70730514`。

2. 对跨行、跨页、双栏、表格和底色/背景图设计实现可验证的布局重排与冲突检测，不可因模型置信度高就直接强改。

## P6｜原版面 PDF 加入可搜索 Unicode 文字层（2026-11-20）

此阶段针对上一阶段**只能观看的图片 PDF**补上可搜索/可复制的中文与英文文字：

- 仍将原始页面画面逐页输出为 JPEG-backed PDF，并在其中放入不可见但有 Unicode 字符映射的文字层；此层按 PDF.js 的原文文字对象生成，已核实原文修改区域必须**从文字层中删除旧文本，替换为已确认的新文本**。输出文件因此可搜索/复制中文字，但它仍然不是完全保留原始可编辑对象的矢量 PDF，更不能承诺任意 ATS 对复杂布局都准确解析。
- 新增 `/Type0` + `Identity-H` + `ToUnicode`（2 字节 Unicode CMap）并在 PDF 页资源字典中正确声明字体。第一次浏览器 QA 发现导出后文字不可搜索，排查为 `/Font` 被错误地放在 `/Resources` 字典外，已修复。真实 Chromium + PDF.js、独立 Poppler `pdftotext`、`pdffonts` 均验证中文可被提取。全文件旧文本不允许错误地重新出现在可搜索文字中。
- 导出过程继续 fail-closed：只接受可信的 PDF.js 原生单行文字、原文确认、长度适配、白底与完整修改集；任何修改无法安全放下，都**拒绝整个导出**而非生成不完整文件。所有原始文件仍然在用户私有 R2 保存，导出只在本地浏览器进行，不向新增外部服务发送简历。
- 新增**客户端下载前再次解析生成文件**：重新打开导出的 PDF 核查页数、所有已确认的新文字存在、旧文字不存在。验收失败则不下载。暂时不需要用户理解模型/解析细节，前端只保留「下载 PDF」及简短的“可搜索、复制文字。投递前请检查排版。”。
- GitHub `HHBA Resume Browser QA` 真实浏览器测试覆盖中文“修改后的简历”被提取、原文 `ORIGINAL RESUME VIEW` 不残留、原版面页数不变；另用独立 Poppler 和 PDF.js 校验产出，测试文件为 `edited-original-searchable.pdf`。首次完成 CI SHA `7e403e4`，9/9 工作流成功。后续再补下载前回读断言，源码见 `resumePdfReviewCopy.mjs` 和 `OriginalResumeViewer.tsx`。

**仍然不是完整原件编辑闭环**：
1. 当前导出 PDF 是图片视觉版面 + Unicode 文字层，而非保留 PDF 可编辑文字对象、字体、矢量图与表格；招聘系统识别复杂版式仍有不确定性。
2. 中文文字实际显示来自安全绘制后的页面图片；文字层使用非嵌入 CID 字体提供 Unicode 映射，未来正式发布还需做更广泛的 PDF 阅读器兼容验证及可访问性/字体嵌入方案。
3. 多行、跨页、彩色背景、双栏冲突的原位置修改仍未实现安全排版重流。
4. DOCX 原始复杂样式预览、原件式编辑与原样式可编辑 Word 导出仍是下一关。
5. 正式视觉模型尚未授权运行，最终真实用户上传→AI Vision→PDF/DOCX 导出闭环尚未验收；PR 继续 Draft，`hhba.work` 不变。
