# HHBA 智能岗位匹配 V2：算法契约与后续数据学习

日期：2026-11-08  
依赖：PR #288（中国大陆一键搜索、统一弹窗）  
本轮：PR #289（独立匹配评分引擎，验收草稿）

## 1. 代码位置与调用顺序

- \`apps/web/functions/_lib/resume-match-core.js\`：只从同版、JD 哈希吻合的已审核 ATS 数据提取候选和任职要求；容许服务端多取至 60 条已核验候选。
- \`apps/web/functions/_lib/domestic-search-fetch.js\`：DeepSeek Search/Fetch 搜索官方职位；搜索发现不等于仍在招聘。
- \`apps/web/functions/_lib/domestic-match-fusion.js\`：只接纳审核过的官方职位/在 24 小时证据窗内的官方搜索详情，再调用 V2 评分、跨来源去重、控制企业多样性并输出 Top 10。
- **\`apps/web/functions/_lib/match-ranking.js\`**：不访问网络、不调用模型、不访问数据库的纯规则算法；核心入口 \`evaluateJobEligibility\`、\`scoreCandidateFit\`、\`inferOfficialSkills\`。上线默认固定经审查版本，个人端不能修改评分权重。
- \`apps/web/src/components/CandidateMatchResultDialog.tsx\`：仅展示企业、职位、分数、国内地点、真实薪资或「未公布」、要求的工作年限和官方入口；不把匹配分误称为录用概率。

## 2. 前置硬筛（比评分优先）

1. 岗位真实来源已在上游核验；未证实的搜索摘要、虚构链接不参与排名。
2. 必须证明实际工作地点是中国大陆城市。港澳台、境外和只有「Remote, China」而无明确大陆地点的职位不能进入。外资企业在中国大陆的真实职位允许。
3. 官方明确有最低工作年限时，简历必须有足以覆盖的工作年限证据；无证据或低于门槛均排除。例：3 年不会推荐最低 7 年职位。
4. 官方明确最低学历时，简历中必须有符合要求的学历证据；不满足或未知均排除。
5. 岗位方向和技能均完全没有相关依据则不推荐；拒绝为了凑 10 条推荐无关岗位。
6. 未公布的任职条件不凭空补齐，不等于「不限」。实际开放状态以企业官网为准。

## 3. 100 分规则模型

| 维度 | 权重 | 依据 |
| --- | ---: | --- |
| 岗位方向 | 30 | 岗位名称与目标方向的准确/同类关联 |
| 技能 | 30 | 简历已证实技能与招聘 JD 明示技能的覆盖比例；未知要求只能得到保守分值 |
| 工作经验 | 20 | 确认满足明确最低年限后，根据覆盖程度评分；未披露年限保守赋分 |
| 学历 | 10 | 满足 JD 明示学历要求；未披露时不当作满分 |
| 工作地点 | 10 | 中国大陆地点真实性是硬门槛，已给出的城市偏好只作弱排序 |
| **总计** | **100** | 分数仅供排序，**不是录用成功率** |

每个推荐包含 \`reference_score\`、\`score_breakdown\` 和 \`ranking_version: HHBA_MATCH_RANKING_V2\`，用户首屏只显示简洁分数，不显示算法日志。

## 4. 反馈学习机制：现在预留、未来受控启动

**此 PR 不新增点击/收藏/投递行为采集，不建立个人训练档案，不开放在线自动训练。**

已实现纯函数 \`proposeFeedbackWeightUpdate\`：它只接受经离线处理的匿名聚合比较结果，至少 200 个独立用户和 500 个已核验反馈结果，产生最多每维 ±3 分、总和仍为 100 的**权重建议**。没有充分数据时返回初始权重；任何建议均不能自动启用。

已实现 \`scoreCandidateFit\` 的**第四个仅限服务端的权重策略参数**：必须携带 \`status:'APPROVED'\`、版本号和合法的 100 分有界权重后才可能启用。当前线上/预览 API 调用并**不传入**该参数，永远使用 V2 审核基线。即使人工批准了新权重，工作地点、最低学历、最低经验等硬门槛仍不可被修改或越过。

未来可在独立隐私及数据质量评审通过之后，考虑使用用户自愿标注的「不合适」、收藏、查看官方岗位、实际投递状态等信号。必须去重、排除机器流量和展示位置偏差，不能将高点击、高收藏等同为岗位质量或录用概率；应采用离线对照、分人群检验、长期效果与负面反馈守护指标，达到要求后再由管理员显式发布新版本。
