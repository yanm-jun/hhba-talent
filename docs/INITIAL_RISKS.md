# HHBA 初始风险清单（Phase 0）

| 编号 | 风险 | 等级 | 说明与应对 |
|---|---|---|---|
| R1 | 审计范围≠用户本机 | 高 | 本轮所有检测在 Hatch 沙盒 VM 执行，**不代表用户真实电脑/云电脑**。应对：`scripts/audit.sh` 可移植，用户本机自查后对照 `docs/ENVIRONMENT_AUDIT.md`。 |
| R2 | 沙盒内存瓶颈 | 中 | 可用内存 <0.5G，Docling/大模型推理不可在此运行。应对：重型组件延迟到用户电脑或云端评估；本沙盒只做轻量验证。 |
| R3 | Docker 缺失 → 本地 PG 未验证 | 中 | 沙盒无 Docker，`infra/docker-compose.yml` 仅做 YAML 语法校验，未实际拉起 PG/pgvector。应对：用户电脑装好 Docker 后按 `docs/SETUP_GUIDE.md` 第 4 步验证。 |
| R4 | 产品定义发生变更 | 中 | HHBA 此前方向为"AI 当包工头"（任务/结算平台，仓库 yanm-jun/HHBA）；本 Phase 0 按新定义"人类能力搜索与连接平台"立项。旧仓库未动，但两个方向的目标、数据模型不兼容，V0.1 立项前需用户明确：新平台是否继承旧仓库/旧域名/129 名执行者数据。 |
| R5 | MCP SDK 大版本 API 变更 | 低 | 官方 Python SDK 已到 v2，v1 示例过期。应对：`docs/DEPENDENCY_LICENSES.md` 已专项核查，代码只用 v2 API。 |
| R6 | 开源许可证传染性 | 中 | OpenCATS 等仓库可能为 GPL/AGPL 类许可证，直接商用有传染风险。应对：`docs/DEPENDENCY_LICENSES.md` 逐项审计结论为"仅供参考"的，一律不引入代码。 |
| R7 | 出站网络走代理 | 低 | 沙盒出站仅走 HTTP 代理；pip/npm 已验证可用。用户本机按常规网络处理即可。 |
| R8 | 远程仓库未建、gh 未登录 | 低 | Phase 0 仅本地 Git 仓库。建远程（建议私有）与推送需用户明确授权，见报告第九节。 |
| R9 | 密钥管理 | 低 | `.env.example` 仅占位符；`.env` 已验证被 `.gitignore` 忽略。风险在于日后有人误把真实密钥写进文档/提交——CI 前加一次 `git status` 检查即可。 |
| R10 | 需求侧冷启动 | 高（产品层） | 沿用既有结论：平台缺的是需求侧与跑通的闭环，前端须承担留住客户职责，注册流程必须显式。V0.1 立项时把"第一个付费/试用企业"作为里程碑，而非功能清单。 |

等级说明：高 = 影响 V0.1 立项决策；中 = 影响开发效率或需用户动作；低 = 已有应对、可控。
