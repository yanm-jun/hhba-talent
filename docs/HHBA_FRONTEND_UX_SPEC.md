# HHBA Frontend UX V1 规格

## 设计原则

1. 首页始终只提供“我要找工作”和“我要招人才”两条主路径。
2. 一页一个主要动作：求职端为上传简历，企业端为描述需求。
3. 不将 `queued`、`parsed`、数据库状态、Worker 和 CSRF 等技术概念暴露给普通用户。
4. 真实授权优先于“顺滑感”：三项授权独立、默认关闭；公开前明确说明公开字段。
5. 没有真实人才搜索时只展示“功能即将开放”，不制造匹配结果或数据。

## 视觉系统

- 背景 `#F8F9FA`，卡片 `#FFFFFF`，正文 `#171717`，辅助文字 `#667085`，边框 `#E4E7EC`。
- 使用 Inter/系统中文字体、12–16px 正文、12–14px 圆角、4/8/12/16/24/32/48/64 间距节奏。
- 仅使用轻量 200ms hover/focus 反馈；`prefers-reduced-motion` 禁用动画。
- 所有操作控件保留可见焦点环，最小操作高度 44px；移动端不依赖 hover。

## 页面契约

### 首页 `/`

保留既定四区：左上 HHBA.、右上登录/注册、居中标题/副标题、两张等宽入口卡。移除开发演示页脚。桌面最大宽度为 664px；390px 时卡片上下堆叠。

### 求职端 `/candidate`

先选择 PDF/DOCX，后登录。文件只保存在当前 SPA 内存中，认证前绝不发送；刷新后为保护本地隐私不会恢复文件。已登录用户可以看到自己的可继续任务。

### 简历整理 `/candidate/resume/:id`

用户可见阶段为“已接收简历 → 正在提取内容 → 等待你核对”。页面从持久化 API 读取任务状态；2500ms 轮询且后台页不请求。失败给出重新尝试和重新上传，成功才允许创建草稿。

### 核对与名片

先摘要后编辑。现阶段能真实编辑展示名称、能力介绍、技能、服务；工作/教育信息仅如实显示已有提取数量。名片使用“核对能力 / 生成名片 / 决定谁可以发现我”三步词汇。企业检索、分享链接、搜索引擎收录分别写入既有授权接口；搜索引擎收录依赖分享授权。

### 企业端 `/employer`

大文本框为唯一首屏主动作。点击“整理需求”只进入原文核对，明确不声称外部大模型推理。登录与组织创建后才能保存真实组织草稿；列表展示草稿、创建/更新时间、编辑，并明确人才搜索尚未开放。
