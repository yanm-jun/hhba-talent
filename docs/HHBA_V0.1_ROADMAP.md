# HHBA V0.1 Phase 1—5 研发路线图

每个 Phase 完成后进行代码审查、自动化测试和范围复核；未满足验收标准不得进入下一 Phase。

| 阶段 | 工作项 | 前置依赖 | 验收标准 | 主要风险 |
|---|---|---|---|---|
| Phase 1：基础域与身份 | 数据库迁移框架、用户/组织/成员、会话、审计基座、API 错误规范 | PRD/数据模型确认；认证方式决策 | 用户与企业组织隔离测试通过；每个认证/写入事件可审计 | 认证设计返工、组织边界遗漏 |
| Phase 2：个人档案闭环 | JSON Resume 导入、受控上传、解析任务/草稿、人工确认、档案版本与可见性/授权 UI | Phase 1；文件存储与保留策略 | 上传数据不自动公开；未确认草稿不可搜索；撤回即时阻断读取 | PII 泄露、Docling 资源峰值、AI 幻觉 |
| Phase 3：企业搜索与联系 | 权限过滤查询、PG FTS/vector 投影、企业搜索 UI、联系申请与个人决策 | Phase 2；搜索排序和企业验证规则 | 跨组织/未授权字段负向测试 100% 通过；联系闭环完成 | 召回质量、推断私人信息、枚举攻击 |
| Phase 4：Agent/MCP | Agent client/委托、MCP v2 tools、限流、工具审计、契约测试 | Phase 3；机器认证和委托产品规则 | MCP 结果与 REST 同策略；过期/撤回委托即失败 | 代理越权、批量抓取、提示注入影响工具参数 |
| Phase 5：运营就绪 | 管理最小队列、删除/导出流程、监控、备份恢复演练、威胁建模、试点发布包 | Phase 1—4；法务/隐私审查 | P0 验收全部通过；恢复和删除演练有证据 | 合规缺口、真实用户支持、运维责任不清 |

## 工作量判断

以 1 个全栈工程师 + 1 名产品/设计投入估计，V0.1 是**中等偏大**的受控系统工程，而非普通简历站：核心难点是授权、审计和数据生命周期。建议按 Phase 做可演示里程碑，不承诺日期；真实用户试点应仅在 Phase 5 后。

## 明确延后

语义重排序/模型供应商接入、公开搜索引擎、收费、SSO、批量 CRM 集成、外部通知、Meilisearch、原生 App 和多区域部署，均在真实使用与安全基线稳定后再评估。
