# Phase 3 站内联系申请流程

## 状态机

```text
draft (企业本地编辑)
→ submitted (企业向个人发起)
→ viewed (个人已查看)
→ accepted | declined | withdrawn | expired
accepted → contact_method_shared (仅当个人明确选择)
```

`submitted` 之后企业不得修改请求正文；可 `withdrawn`。个人只能处理发给自己的请求。重复未关闭请求按企业组织、个人、需求去重并限频。

## 数据最小化

联系申请含：组织 ID、需求 ID（可选）、候选人 profile ID、发送者成员 ID、简短目的、状态、时间戳。默认不含电话、微信、工作邮箱和原始简历。个人接受后仍只显示其明确选择的联系方式；V0.1 可以只完成“接受/拒绝”并提示后续站内沟通。

## 服务端策略

- 创建时重新检查企业已审核、成员有效、档案 confirmed、`enterprise_search` 仍为 true。
- 个人撤销企业检索授权后：新的申请拒绝；已有申请不自动泄露任何新资料，个人可见历史并可撤销。
- 每次创建、查看、处理、撤回均审计资源 ID 与结果；不得把消息正文或联系方式写入普通应用日志。

## 企业端体验

候选卡仅一个主要动作“申请联系”。提交前明确说明不会取得私人联系方式。状态页显示“已发送 / 已查看 / 已接受 / 未接受 / 已撤回”，不显示推测性的已读时间以外的隐私信号。
