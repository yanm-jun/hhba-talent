# HHBA｜156 家企业独立图片制作任务书（供 Codex 执行）

> 数据来源：用户提供的 2026-10-28 秋招名单截图，按现有 HHBA 企业编号完整保留。**截图中的“7日内更新”“3日内截止”是当时的截图栏目标签，并非今天仍在招或仍未截止的证明。**

## 一、任务目标

- 为下面 **156 家不同企业**准备每家 **2 张完全独立的图片**，目标合计 **312 张单独文件**；**不允许生成拼图、九宫格、网页截图、宣传海报再裁切冒充独立生成**。
- 每家第 01 张建议为与已核实业务匹配的建筑／生产／服务／运营场景，第 02 张建议为独立的办公／研发／工程／服务工作场景。两张必须分别创建、分别校验，不能同一图裁切、调色、换字后充数。
- 企业 **Logo 另行处理**：首先查真实官方品牌素材；允许以真实官方图为底图做清晰化、矢量化修复，但不得凭文字猜测绘制商标，不得把 AI 臆造 Logo 当作官方标志。
- 真实企业照片与 AI 场景图分开标记：**AI 生成图只能标为“AI 场景示意／非企业实景”**。不得在生成的虚构建筑、厂房、前台上加企业名称／官方 Logo 来假装真实办公场所。
- 图片只为 HHBA **GitHub 静态测试版**制作、展示和验收，**不要自行部署阿里云正式环境，不要修改真实数据库或既有招聘流程**。

## 二、执行流程与验收

1. 从本文件的企业 ID 逐条处理，首先查清企业主体：部分名称是品牌、简称、集团或子公司；身份不确定时先标记 `identity_pending`，不得张冠李戴。
2. 调查企业主营业务及官方品牌资料，保留参考资料 URL。为每家分别写出两个互不重复的场景描述，不得用“标准玻璃写字楼”批量套图。
3. **逐张生成、逐张保存**，每一次生成只交付一幅独立图像，不拼贴多张。推荐横版 16:9，至少 1280×720，优选 1920×1080，WebP 或 JPG；保留原图。
4. 按 `assets/{企业ID}/{企业ID}_01.webp`、`assets/{企业ID}/{企业ID}_02.webp` 逐张落盘。不要改企业编号，不要用中文名称直接作为唯一键。
5. 每张做人工或自动质检：图片可打开、不是拼图或带 UI 的截图、场景与企业业务不冲突、无错误文字／Logo、与其他图没有明显重复；保留宽高、文件哈希及源信息。
6. 输出 `manifest.csv` 或 `manifest.json`，至少含 `company_id,company_name,image_01,image_02,image_type,source_url,review_status,notes`；每图分开记录来源与核验状态。
7. 仅把实际通过质检的独立文件加入 ZIP。最终 ZIP 中应有 **156 个企业目录／312 张独立图片**；不能完成时报告真实完成数与缺失 ID，严禁以重复图、拼图拆图或空文件凑数。
8. 网站侧必须保留“点企业 Logo／名称进入 HHBA 站内企业详情”“访问企业招聘官网需完成注册登录验证”的原有规则；前端修改先出 GitHub 预览，用户验收后才考虑正式部署。
