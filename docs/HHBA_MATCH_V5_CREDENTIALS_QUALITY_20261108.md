# HHBA 智能匹配 V5：职业资格证据与推荐质量验收

日期：2026-11-08。基础分支依赖 PR #294、#293、#292、#291、#290、#289、#288。
本 PR 不修改 main、不更新 hhba.work。

## 一、为什么需要单独检查职业资格

仅靠“目标职业相同”“本科”“有工作经验”不能证明能够申请所有特殊岗位。
例如，官方护士执业注册规定涉及取得护士执业证书及注册。
参考：
- 《护士条例》（司法部国家行政法规库）：https://xzfg.moj.gov.cn/front/law/detail?LawID=209
- 国家卫健委《护士执业注册管理办法》2021 修订：https://www.nhc.gov.cn/fzs/c100048/202101/d36062c0fa4c49c4a818c9c0efa4728e.shtml

这**不是通用的证照法律合规引擎**，也不假设任何职业的所有招聘必须持有同一证书。每个具体岗位的申请资格，仍需使用相应招聘官网原文和主管部门规则核对。

## 二、实现

1. 新模块 \`functions/_lib/professional-credentials.js\` 将 8 类常见职业资格名称区分，尤其不会混淆：
   - 护士执业证书与护士执业资格证书；
   - 医师执业证书与医师资格证书；
   - 律师执业证书与法律职业资格证书；
   - 教师资格证书和其他学历/专业名称；
   - 注册会计师证书与会计等职业名称。
2. 只对**官方 JD 任职要求明确为必须/应持/要求持有**的证书加硬筛。优先/加分/明确入职后再取得/未列出的证书不做凭空的“全部应有”门槛。
3. \`verifiedProfile\` 直接从申请人的简历文字查找“已取得/持有”等自述语境，不让 DeepSeek 猜测、增加或替换证书；“正在备考/尚未取得/未持有”不计入。
4. 有证书自述，仅表示**简历有文字依据**，不代表原件、注册状态、有效期、适用执业地点等经过外部核验。不收集、不存储证书号码或扫描件。推荐理由必须提示该限制。
5. 对护士、临床医师、执业律师和中小学/幼儿园教师等职位，在 JD 未明确写证书时，标注**需进一步核实资格**，不捏造任何法律门槛；不对“律师助理”“法务专员”“舞蹈教师”等通用岗位误施加执业门槛。
6. \`match-ranking.js\` 明确证书要求未被简历证实时，返回 \`PROFESSIONAL_CREDENTIAL_NOT_EVIDENCED\`，不进入主要 Top 10；即使其他维度 100 分也不允许绕过。

## 三、推荐质量评估

新增 \`functions/_lib/match-quality-evaluator.js\` 纯函数以及 V5 测试。

离线标注输入只需案例类别、预期相关岗位 ID 和返回岗位 ID、官方链接、是否违反硬条件。
报告输出仅聚合指标：
- 推荐 Top 1 相关率；
- 返回岗位中的人工标注相关岗位比例；
- 至少一条相关岗位的覆盖率；
- 资格、学历、工作年限等硬门槛误入次数；
- 重复岗位 ID 和无效链接；
- 分职业类别的 Top 1 和覆盖率。

这套功能没有调用真实招聘官网或个人邮箱、没有新增前端行为采集或数据库追踪。测试中的企业/岗位都是合成数据，**绝对不能将模拟 100% 准确率对外称作平台真实匹配率**。

## 四、验收边界

- CI 同时检查完整匹配算法、国内 Search/Fetch、Cloudflare Pages API 和 TypeScript/Vite 构建。
- 实际上岗资格审核、证书真伪核验、监管政策最新有效性、招聘仍开放状态：不由本轮代码直接证实。
- 在真实用户环境启用前，需要用户授权，建立经过脱敏的代表性评测样本；按专业分组人工评价召回率与误推风险，且不能直接保存身份证、证件号码、完整证照或未授权简历。
- 通过自动化不代表 Cloudflare Preview 已正常部署；待预览验收后再依次合并依赖分支。
